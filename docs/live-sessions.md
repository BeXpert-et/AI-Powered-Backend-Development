# Live session format and instructor guidance

There are two live sessions each week, one hour each. Students learn implementation basics through recordings and practice.

## Instructor workshop — 60 minutes

| Time | Activity |
|---|---|
| 0–5 min | Recall a previous concept |
| 5–15 min | Explain a difficult concept or tradeoff |
| 15–35 min | Work through a real debugging or design scenario |
| 35–50 min | Student problem-solving and discussion |
| 50–60 min | Review solutions and clarify the weekly assignment |

The instructor should prioritize **why an implementation works, where it fails and how to verify it**. Installation walkthroughs, routine syntax and basic scaffolding belong primarily in recordings.

## Student demonstration and review — 60 minutes

| Time | Activity |
|---|---|
| 0–5 min | Common issues and review agenda |
| 5–40 min | Five rotating student demos, seven minutes each |
| 40–50 min | Group debugging or code review |
| 50–60 min | Peer feedback and next improvements |

With up to ten students, presenters rotate weekly. Everyone still submits their work every week.

A demo covers the working feature, implementation choices, error or edge cases, and reviewer questions. Instructors ask students to explain decisions rather than just show running code.
